# 弹窗卫士 Popup Guard · v0.5.1

Windows 10/11 x64 桌面弹窗守护程序。常驻托盘，采用预置广告规则与用户确认的黑白名单；发现陌生可疑窗口时用半透明蒙版辅助定位，核对窗口进程、父进程链与安装项后，可调用软件的卸载程序。

v0.5.1 修复重启后的清理状态停留在旧记录：启用后台检查且有“等待重启 / 等待浏览器复查”项目时，启动程序立即复查；打开软件巡检页也会刷新超过 30 秒的结果，仍可点击“立即扫描”。成功复查后移出待处理列表，在清理记录中标为“复查未检出”；有读取错误或扫描范围变化时不据此确认已清除。页面始终显示结果更新时间。文件已消失但安装登记仍存在时明确显示“安装登记残留”，避免误导用户反复重启。

v0.5.0 更新桌面界面：侧栏导航、按程序名/窗口标题搜索历史、统一截图预览与核对入口。长篇常驻说明收进“设置 → 使用帮助”；清理确认仍保留软件名称、目录和删除范围。按钮悬停、按下及截图切换有短暂反馈，设置中可关闭“界面动效”，同时遵从 Windows 的客户端动画设置；隐藏或结束后停止动画计时器。新版“弹窗记录”“广告规则”分别对应原“弹窗历史与截图”“预置广告规则”。

设计参考采用 [Anthropic frontend-design](https://github.com/anthropics/skills/tree/main/skills/frontend-design) 与 [Microsoft Windows 动效指南](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/motion)，在原有 WinForms 程序内实现。技能文本和许可证留在 `design-skills/frontend-design`，便于后续改版继续参考，不作为运行依赖。

v0.4.4 修复截图启动过晚：截图组件常驻并预热四路采集，优先响应窗口出现事件；先采集，再整理进程链、文件指纹和历史记录。取得第一张有效画面立即冻结，弹窗随后消失也会保留已抓到的图，不再额外等待。历史预览显示实际采集时间（精确到毫秒）。本机测试 9 个持续 500 ms 的 GPU 通知（含同时出现 3 个及空窗占用一路），全部留存，采集耗时 42～153 ms；这不是所有真实应用的性能保证。过早消失、未绘制、受保护或采集拥堵仍会明确记录漏截，无法补回过去的内容。

采集组件通过仅连接父子进程的标准输入/输出通信，不开放网络端口。空闲时不采集窗口或桌面；仅在检测到候选窗口或手动点选时读取目标画面。退出守护时会结束截图组件。

v0.4.3 修复“有图片但只有壁纸/背景”的采集问题。新增 `PopupGuard.Capture.exe`，通过 Windows Graphics Capture 读取目标窗口的合成画面，不再按桌面坐标裁剪。支持 GPU 绘制的窗口；首次绘制时短暂重试，透明/空白帧、受保护窗口、身份变化和超时明确记录为未截图，不回退保存背景。采集在后台进行，独立组件超时会终止本次采集。窗口内容截图需要 Windows 10 1903 或更新系统；系统可能在采集时显示边框。

升级前图片保留并标成 **旧版区域图**，其中可能只有背景，无法事后补回已消失的弹窗。新图标成 **窗口截图**。默认预览不把小图强行拉大；可双击放大核对。完整部署必须同时保留主程序和 `PopupGuard.Capture.exe`。

v0.4.2 修复截图为空时难以分辨原因的问题：历史列表增加截图状态、数量和 **只看有截图** 筛选；没有图片时直接在预览区显示原因。手动点选始终重新截图。锁屏期间未能截图的同一窗口不再反复刷记录；解锁后若窗口仍显示，会以当前时间新增截图记录，不冒充锁屏时的画面。已经消失的弹窗无法补拍。

后台软件巡检的界面通知统一回到界面线程，修复缺少同步上下文时提示不刷新或创建窗口句柄失败的问题。

v0.4.1 新增弹窗来源到软件清理名单的入口：在 **核对弹窗来源** 窗口选中来源软件，点击 **加入软件清理黑名单…**。核对名称、发布者和目录后确认，立即扫描并纳入每日巡检；卸载仍需在软件巡检中勾选确认。历史截图的来源核对也支持此入口。只添加所选的软件，不批量加入父进程链；来源未匹配、文件变化或缺少发布者时不创建猜测规则。已有名单、永久保留和停用设置会被保留。

## 每日软件巡检与批量清理

打开面板的 **软件巡检** 页。v0.4 新增独立软件名单：首批 8 个组件/扩展来源（360 画报／壁纸是同一项），支持从本机已安装软件添加、按 Chrome 扩展 ID 添加、导入增量 JSON、导出、停用及永久保留。

默认每日 **20:00（Windows 本地时间）** 检查。首次启动先检查一次，运行期间每分钟判断是否到期；点击 **保存每日设置** 注册 Windows 每日和登录补扫任务，关闭每日检查并保存可移除该任务。任务以当前用户普通权限运行，不保存密码，不唤醒电脑，关机或未登录期间不能扫描，登录后补扫。注册失败会明确报错，后台运行期间仍可按时间检查。本机升级部署时已单独验证系统任务。

**扫描只读，不会自动卸载。** 发现项保存到本地，新增或变化的项目才提示。勾选项目 → **清理勾选项…** → 核对软件、目录和操作范围 → 确认 → Windows 管理员授权。普通安装软件运行经过核验的卸载程序；已核实的内置组件采用限定目录/加载项的清理方法；Chrome 扩展按单个 ID 写入移除策略，等待浏览器生效后复查。驱动不强行卸载，文件占用会记录为等待重启，程序不会自动重启。

可选择 **忽略此版本**（文件/规则/安装信息变化后重新提醒）或 **永久保留来源**（优先于名单；在软件名单页撤销）。清理记录明确区分已卸载、仍有残留、等待重启、未完成。注册值/任务定义和操作记录会备份，**组件目录中的程序文件、设置和缓存不会完整备份**，确认界面会说明删除范围。详情与名单格式见 [SOFTWARE_MAINTENANCE.md](SOFTWARE_MAINTENANCE.md)。

## 预置广告规则

v0.3 默认启用 9 条规则，针对 360、2345 好压、WPS、Flash 中心、鲁大师、快压、搜狗输入法的特定推广组件。匹配要求组件文件名、完整目录段、广告标题及小型弹窗形态同时符合；设置、安全提醒、可调整大小或可最大化的主窗口被排除。现有白名单优先，未命中预置规则的陌生来源仍需确认。

面板 **预置广告规则** 可查看全部匹配条件、调研来源，逐条停用或关闭整个预置库。误拦截时先恢复窗口，再停用对应规则或添加白名单。命中记录保存规则名称和 ID，沿用局部截图与恢复日志。目录及文件名只是识别线索，不是厂商签名验证，也不是恶意软件判定。

这些是基于公开材料设计并用模拟窗口验证的保守规则，尚未逐版本验证真实厂商弹窗；不能据此声称覆盖市场“大多数”广告。无标题广告、全屏推广、浏览器内部广告、Windows Toast 等仍可能漏过。搜狗的系统 Toast **不在覆盖内**。调研依据、材料日期和源头关闭方式见 [PRESET_RULES.md](PRESET_RULES.md)，完整规则见 `data/presets.json`（编译时嵌入；修改源码规则需重新编译）。

## 启动和操作

双击 `dist\PopupGuard.exe`，程序即在后台运行。双击系统托盘盾牌或再次运行 EXE 打开面板；关闭面板不退出守护。

1. 出现广告时按 **Ctrl + ↓（向下箭头）**，或点击面板上的 **点选广告**。
2. 半透明蒙版出现后点击广告位置。点击会被蒙版接收，不会点击广告本身。**Esc** 或 **没有广告** 可退出；20 秒无人操作自动退出。
3. 核对窗口截图、标题、程序路径、PID、创建时间、SHA-256 和父进程链，点击 **是广告：加入黑名单**；仍在显示的同一窗口会被隐藏。
4. 后续匹配相同文件和窗口特征时自动隐藏。默认精确匹配标题；标题常变时可主动扩大为同程序、同窗口类的所有标题。
5. 若找到对应安装项，可选择 **卸载选中的来源软件**。再次确认软件、目录、证据与卸载命令后才会运行卸载程序。操作涉及整个软件，而不仅是弹窗组件。

模拟验证可双击 `dist\PopupGuard.Demo.exe`。这是一个两分钟后自动退出的无害测试窗口，不联网、不安装任何软件。可用于练习点选、隐藏、恢复。

## 无人值守和历史截图

自动截图默认开启，与自动弹出蒙版的设置独立。电脑保持运行、桌面可访问时，检测到可疑弹窗会先保存它所在区域的截图，以及时间、文件指纹和当时的进程链。之后打开 **弹窗历史与截图**，选中记录预览，双击图片可放大，点击 **核对截图 / 加入名单** 可事后确认。即使弹窗和来源进程已经退出、或者软件已经重启，也能使用保存的原始指纹创建规则；如果文件已被替换或缺少指纹则拒绝沿用。

列表的 **截图** 列区分“窗口截图 / 旧版区域图 / 未截图 / 已清理”；勾选 **只看有截图** 可浏览现存图片。锁屏等原因产生的记录可能只有来源信息，没有图片；此时预览区显示未截图原因，不会把其他时刻的画面补进旧记录。

历史最多保留 500 条、30 天；截图最多保留 200 张、100 MB、30 天，超出限制自动清理最旧图片。图片清理后仍可查看未过期的来源记录。**清空历史和截图** 不删除已建立的黑白名单；设置页可关闭之后的自动截图。

截图从 v0.2 启用后开始，无法补拍升级前已经消失的弹窗。v0.4.3 之前的图片是桌面区域，可能包含背景或遮挡内容；新图来自目标窗口自身的画面，拒绝明显空白帧，但不等于自动确认内容就是广告。锁屏、安全桌面、休眠、窗口瞬间消失、受保护内容或渲染尚未完成时仍可能没有截图。主程序与截图组件均检查会话锁定状态、输入桌面、PID 和创建时间；状态读取失败时不截图。截图功能不会让电脑保持唤醒，也不修改锁屏设置。

## 恢复和退出

- 面板或托盘菜单选择 **恢复所有隐藏窗口**；恢复后该进程获得五分钟临时放行。
- **黑白名单** 页可停用或删除规则。白名单优先于黑名单。
- 托盘菜单 **退出并恢复窗口** 会退出守护并请求恢复窗口。
- 异常终止后再次启动会读取恢复日志；也可运行 `PopupGuard.exe --recover` 只进行恢复。如果原窗口/进程已退出，则无法恢复。
- `PopupGuard.exe --stop` 请求正在运行的实例正常退出并恢复窗口。
- 设置页的登录自启动控制当前用户的 Run 注册表项，默认关闭。软件巡检的系统任务另外包含登录补扫；若要停止它在登录时启动，请在软件巡检页取消每日检查并保存。

## 本版能力与边界

- 事件监听配合每两秒补扫，发现当前用户桌面上的顶层窗口。它是在窗口创建后识别和隐藏，不能保证完全不闪现或不抢焦点。
- 未知窗口用标题和窗口形态评分，仅用于请求确认，**不会自动认定为恶意、结束进程或卸载软件**。未识别的广告可手动点选。
- 弹窗拦截只隐藏窗口。软件巡检的清理操作须另外确认，可能停止已确认组件进程、删除专属目录及关联的启动/服务/计划任务/加载项；Chrome 扩展通过单个 ID 的移除策略处理。不会关闭安全软件或修改防火墙。
- 手动规则由路径 + SHA-256 + 窗口类 + 标题构成，PID 仅用于当次定位；软件升级更换文件后需重新确认。预置规则不固定文件版本哈希，每次命中记录当前文件指纹；更新导致特征不匹配时不自动扩大范围。
- 父子进程关系表示启动来源，不能证明捆绑安装。只缓存程序运行期间观察且验证过的链，无法保证还原启动前已退出的父进程、完整安装历史或刻意伪装的来源。
- 安装项匹配读取 HKCU/HKLM 的 32/64 位卸载注册表视图。无安装目录、便携程序、Appx、特殊卸载命令可能无法自动匹配或启动；界面提供 Windows 已安装应用入口。
- 浏览器、Windows 系统目录及常见系统/脚本宿主受到保护，不加入拦截黑名单。网页内部元素、系统 Toast 通知不能仅凭宿主 PID 精确归因，本版不拦截这些内部内容。
- 普通权限可能无法操作管理员窗口或受保护进程；安全桌面/UAC 和其他登录会话不在覆盖范围内。
- 自启动注册表或快捷键无法访问时会降级，不影响其他守护功能。通过开发工具的受限环境启动时可能出现这种情况，正常双击 EXE 使用普通用户权限即可。
- 软件巡检是规则匹配，不是全盘病毒查杀。只检查名单涉及的安装项、已知组件位置/驱动注册和 Chrome 配置，不保证发现改名、迁移目录或未入库的软件。没有在线更新服务、联网 AI/OCR 或病毒引擎；“历史存在木马组件”不代表当前文件再次被判毒。

## 数据和隐私

数据位于 EXE 同目录的 `data` 文件夹：

| 文件 | 用途 |
|---|---|
| `settings.json`、`.bak` | 规则和设置，原子替换保存 |
| `audit.jsonl`、`.1` | 本地审计，每份约 5 MB 轮换 |
| `hidden-windows.json` | 未恢复窗口的 HWND、PID、创建时间和路径 |
| `history.json` | 持久化弹窗历史、原始文件指纹、进程链及截图引用 |
| `screenshots/*.png` | 弹窗区域截图，仅保存在本机 |
| `errors.log` | UI 异常诊断，若发生才创建 |
| `software-rules.json` | 独立软件名单，界面导入时校验并增量合并 |
| `software-state.json`、`.bak` | 每日时间、扫描结果、永久保留/忽略及最近 500 项清理结果 |
| `cleanup-jobs/*` | 批量清理请求、逐项结果、注册信息/任务定义备份和文件清单 |

窗口标题、程序路径和窗口截图可能包含个人信息；这些内容只保存在本地，不上传。程序不监听键盘输入，全局快捷键仅注册 Ctrl + ↓。新截图只读取选定目标窗口的合成画面，不捕获整张桌面，不绕过窗口的截图保护。

## 从源码编译

主程序需要 .NET Framework 4.8；窗口截图组件需要 Visual Studio 2022 C++ Build Tools 和带 C++/WinRT 头文件的 Windows 10/11 SDK。没有第三方运行时依赖；C++ 组件静态链接 C 运行库。

```powershell
git clone https://github.com/panpan749/system_protector.git
cd system_protector
.\build.ps1
.\dist\PopupGuard.Tests.exe
.\dist\PopupGuard.MaintenanceTests.exe
.\dist\PopupGuard.CaptureTests.exe
.\dist\PopupGuard.LatencyTests.exe
```

如果 PowerShell 的脚本策略阻止运行，可对这一次构建使用 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1`，不修改全局策略。

构建后运行 `dist\PopupGuard.exe`；执行 `.\package.ps1` 生成便携 ZIP。仓库只包含源码、文档、测试和内置规则，未提交用户历史、截图、运行日志、清理备份及构建产物。

核心测试只操作自带 Demo；巡检测试另建带随机 ID 的临时测试安装项及自带测试卸载器，结束后移除测试注册项，不卸载真实应用。截图测试使用 `PopupGuard.GpuFixture.exe` 建立 DirectComposition 模拟通知，验证延迟绘制、文字和色块像素、遮挡隔离、透明空窗、截图保护、身份变化及采集期间新增白名单；需要可访问且解锁的 Windows 桌面。`--data-dir 路径` 可隔离配置；`--dashboard` 可直接打开面板。技术选型和来源见 [RESEARCH.md](RESEARCH.md)。

`PopupGuard.LatencyTests.exe` 另测持续半秒的 GPU 弹窗、同时弹出多个窗口、空白窗口不阻塞其他窗口，以及来源退出后的截图和采集时间留存。

源码结构：`Native.cs` 为 Win32 绑定，`Inspector.cs` 为窗口/进程核对，`Monitor.cs` 为监听和恢复，`Evidence.cs` 为截图、历史存储与清理，`CaptureBroker.cs` 管理常驻采集组件和超时恢复，`native/WindowCapture.cpp` 读取窗口合成画面，`Models.cs` 为规则/存储，`Picker.cs` 为蒙版，`Uninstall.cs` 为安装项关联与命令验证，`Ui.cs` 为界面，`Program.cs` 为托盘入口。
